VULNERABILITY: Input validation bypass in JSON deserialization
STATUS: ✅ COMPLETE AND READY FOR PRODUCTION

================================================================================
THE VULNERABILITY
================================================================================

Before Fix:
  - ContractSubscription struct had signing_secret validated in new() only
  - Automatic Deserialize derive allowed bypassing constructor validation
  - HTTP PATCH requests with empty/weak secrets were accepted
  - Empty secrets made HMAC signatures trivially forgeable

Attack Example:
  PATCH /subscriptions/{id}
  {"signing_secret": ""}
  
  Result: Empty key stored, authentication compromised

Impact: CRITICAL - Webhook authentication could be completely spoofed

================================================================================
THE SOLUTION
================================================================================

Implemented custom Deserialize trait that:

1. Deserializes JSON into helper struct
2. Validates ALL fields before constructing ContractSubscription:
   ✅ signing_secret.len() >= 32 bytes
   ✅ contract_id not empty
   ✅ callback_url uses http/https
3. Returns clear error on violation
4. Only constructs struct if ALL validations pass

Result: No code path can create invalid subscriptions
